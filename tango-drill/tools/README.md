# 学習記録を切らさないための道具

学習記録は項目のIDにひも付く（IDの作り方は `ids.js` の先頭）。見出し語や番号を直すとIDが変わるので、
記録を新しいIDへ移す対応表（`../src/migrations.json`）と、IDが消える更新を止める検査を置いている。

- `ids.js` … 完成版の HTML から全項目のIDを取り出す（`node tools/ids.js [完成版.html]`）。
- `ids_baseline.json` … 基準。公開中の版のID一覧と版番号。
- `check_ids.js` … 基準の各IDに、基準の版より新しい移行を当てた行き先が、新しい完成版にあるかを確かめる。
  `node build.js` が書き出しの後に自動で行い、失敗すると終了コード1（`SKIP_ID_CHECK=1` で飛ばせる）。
- `update_baseline.js` … 基準を、いまの完成版のID一覧と版番号で更新する。

## IDが変わる修正をしたとき

1. `src/migrations.json` に対応を足す。形は `[{"v":1,"map":{"旧ID":"新ID"}}, {"v":2,"map":{…}}]`（`v` は1からの連番。`note` に覚え書きを書いてよい）。
   - 項目そのものが無くなったときは、値を `null` にする（`"旧ID": null`）。その記録は消え、検査では「消えたID」に数えない。
   - まだ公開していない移行は書き換えてよい。公開済みの移行は書き換えず、次の番号の移行を足す。
   - 1つの移行は「同時の付け替え」。同じ移行に a→b と b→a を書けば入れ替えになる。
     a→b と b→c を同じ移行に書くと、a の記録は b に、b の記録は c に移る（a を c へ移したいなら a→c と書く）。
2. `node build.js` を実行する。「IDの検査: OK」になるまで対応を直す。
3. `node --test` でテストを通す。
4. 公開したら `node tools/update_baseline.js` で基準を更新する（検査に通らない完成版では更新されない）。

## 検査で分からないこと

番号で決まるID（古文330 `b:番号`、関連語 `br:番号:順`、読み `y:番号`）は、番号や並び順を付け替えると
IDは残ったまま中身の語だけが入れ替わる。これは検査では見つからないので、番号や関連語の順を変えたときは
必ず対応を `migrations.json` に書く。
